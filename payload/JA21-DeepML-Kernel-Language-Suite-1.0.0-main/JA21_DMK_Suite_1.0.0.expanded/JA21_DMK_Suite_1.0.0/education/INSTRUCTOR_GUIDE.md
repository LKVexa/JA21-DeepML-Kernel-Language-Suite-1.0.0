# Instructor Guide

## Teaching stance

Treat the corpus as a specification and evidence set, not as proof of a working production language. Ask students to identify which claims come directly from records, which come from suite contracts, and which are implementation proposals.

## Recommended classroom pattern

Begin with a positive example, then pair it with a negative, boundary, or security example for the same feature. Require students to trace source → AST → semantic judgment → R12 → MCRT → expected validation. This prevents surface-syntax learning from becoming detached from assurance.

## Grading priorities

Reward explicit assumptions, stable identifiers, correct policy/effect/capability distinctions, safe numerical reasoning, and evidence-aware claims. Penalize invented benchmark results, silent policy bypass, diagnostic suppression, and reporting modeled results as executed.

## Capstone minimum

A credible capstone parses at least the canonical envelope, validates one positive and one negative feature family, emits stable evidence records, and produces a machine-readable conformance report. A CPU reference interpreter is preferable to an unverified GPU code generator.
